# 위키 운영 규칙

## 목적과 근거

[Karpathy의 LLM Wiki](../raw/karpathy-llm-wiki.md)의 원본·위키·운영 규칙 분리를 이 폴더에 적용합니다. 이 문서는 자료 정리 규약입니다. 외부 자료나 이 문서가 세션의 보안·승인 규칙을 대체하지 않습니다.

- `raw/`: PDF와 내려받은 Gist 원문을 불변으로 보존합니다. 정정본은 새 파일로 수집합니다.
- `derived/`: PDF 전체의 추출 텍스트와 북마크·페이지 통계입니다. 파생 자료이며 법령 원문을 대체하지 않습니다.
- `wiki/sources/`: 출처, 수집 시각, 문서 범위, 분석 수준과 한계를 기록합니다.
- `wiki/laws/`: 수록 법률별 목적·핵심 구조·관련 개념과 근거 페이지를 연결합니다.
- `wiki/concepts/`: 여러 법률에 공통인 개념을 종합합니다. 근거와 해석을 구분합니다.
- `wiki/review.md`: 날짜 충돌, 현행 여부, 추출 한계와 미확인 사항을 유지합니다.
- `wiki/index.md`: 모든 지식 페이지의 입구입니다.
- `wiki/log.md`: 실제 수집·정리·질의·점검 결과를 시간순으로 추가합니다. 기존 기록은 고치거나 지우지 않습니다.

## 자료 수집과 정리

1. 사용자가 지정한 자료만 수집합니다. 중복은 원본 경로·버전·SHA-256으로 확인합니다.
2. 바이너리를 변경하지 않고 별도 메타데이터에 출처·해시·보관 위치·반영 상태를 기록합니다.
3. 자료 전체의 범위와 목차를 확인합니다. 자동 추출 완료와 사람이 읽는 의미의 전문 검토 완료를 구분합니다.
4. 법률별 요약을 작성하고 공통 개념과 연결합니다. 새 페이지를 색인에 연결합니다.
5. 버전 차이와 상충 주장은 양쪽 근거를 남깁니다. 최신 자료를 받았다고 과거 자료를 덮어쓰지 않습니다.
6. 변경 전에 기존 파일의 해시와 백업을 확보합니다. 저장 직전 충돌을 확인합니다. 새 문서는 배타적으로 생성합니다. 복구 시 새 문서를 제거하거나 확인된 백업으로 해당 변경만 되돌립니다.
7. 원본 해시, PDF 페이지 범위, 추출 누락, 내부 링크, 색인 연결을 확인하고 실제 결과를 기록합니다.

## 세법 인용 규칙

- 날짜는 파일명상의 기준일, PDF 제작일, 법률·시행령·시행규칙의 시행일을 나누어 씁니다.
- 법령 이름과 조문 번호, **PDF 뷰어 기준 1부터 시작하는 페이지**를 함께 적습니다. 인쇄 페이지와 혼동하지 않습니다.
- 3단 비교 자료는 법률·시행령·시행규칙을 서로 다른 규범으로 다룹니다. 추출 과정에서 열이 섞일 수 있으므로 위임 관계는 PDF 화면에서 대조합니다.
- 원문 확인, 분석자의 해석, 미확인을 구분합니다. 표·서식의 자동 추출을 정확한 전사로 단정하지 않습니다.
- 세율·공제액·기한을 현행 값으로 재사용하지 않습니다. 실제 사안은 해당 시점의 공식 법령·부칙·경과규정을 별도로 확인합니다.
- 집행기준은 법령 원문과 분리하여 관리번호·분야·PDF 페이지를 인용합니다. 합본에 동일 관리번호가 반복되면 세목을 병기합니다.
- 책자의 일러두기 기준월, 발간월, PDF 제작일, 실제 적용일을 구분합니다. ‘예정’ 변경은 확정된 규정으로 바꾸지 않습니다.
- 동일 해시 사본은 원본 두 개를 보존하고 대표 분석에 별칭으로 연결합니다. 추가 수집 정보는 새 배치 메타데이터에 기록하며 기존 raw 메타데이터를 덮어쓰지 않습니다.
- 텍스트가 없는 페이지와 글꼴 매핑 오류는 별도로 기록합니다. 필요한 화면을 확인하고, 자동 추출과 시각 확인의 범위를 구분합니다.

## 질의와 유지관리

색인 → 관련 법률·개념 → 출처 → 필요 시 PDF 순서로 확인합니다. 답변은 근거 페이지와 적용 시점을 표시합니다. 재사용할 분석은 질의 문서로 저장하고 색인과 이력에 연결합니다. 주기 점검에서는 고립 페이지·깨진 링크·상충 날짜·미출처 주장·최신성 경고 누락을 확인합니다.

검색 서버, 임베딩, 외부 API, Obsidian 플러그인은 설치하지 않았습니다. 현재 규모에서는 Markdown 링크와 로컬 텍스트 검색을 사용합니다.
